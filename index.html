Case studies

Ask Your Documents

Ask questions of your own PDFs and notes, and see exactly which passage each answer came from. Double-click to run; no API key needed. FAISS dense retrieval and BM25 fused with Reciprocal Rank Fusion, citations validated against the passages they point at, and a plain "not in your documents" when the answer isn't there.

What measuring it showed

On terse keyword queries, dense retrieval dropped to 0.667–0.800 recall@3 where BM25 scored 1.000 — and at k=3, BM25 alone was the safest retriever, not the hybrid I had built.

Two later surprises came from the same harness. Swapping the embedding runtime for a 10× smaller install moved recall 13 points: the “same” model gave different vectors. And CI scored differently from my laptop with identical code, because rank-fusion ties were broken by absolute file paths.

Port Analyst Agent

A tool-calling agent that answers analytical questions about container terminal operations by writing read-only SQL against a DuckDB star schema, with a bounded reasoning loop, self-correction on query errors, and a full trace of every tool call and token.

What measuring it showed

An ablation withheld the schema from the system prompt and made the agent discover it through tools. Accuracy was identical — and prompt tokens went up 5%, because discovery calls accumulate in the conversation faster than the schema block ever cost.

What did change was knowing when something is absent: asked for revenue the warehouse does not record, the agent without the schema spent its entire step budget hunting for a column to hold it. Correct declines halved, from 1.000 to 0.500.

How I work

  • The evaluation is the product

    Anyone can assemble a retrieval pipeline. The harder and more useful part is the harness that tells you when it is wrong — and both of these projects exist mainly because building that harness changed what I shipped. It has contradicted me more than once, and each time I wrote it down.

  • Guardrails are controls, not requests

    Asking a model to "only write SELECT statements" is a request. Parsing every statement before it reaches the database — rejecting stacked statements, DML hidden inside a CTE, and DuckDB's file-read functions, over a connection that is independently read-only — is a control. Everything that reaches a model is untrusted input, including a row of data echoed back into its own context.

  • No agent framework

    The chunking, the hybrid retrieval, the rank fusion, the agent loop, the tool dispatch and the provider adapters are all written out. Partly for control, but mostly because the interesting decisions live exactly where a framework would have quietly made them for me.
