Ask Your Data

A text-to-SQL agent, live on open models

Ask a spreadsheet or a database a question in plain English. A tool-calling agent explores the tables, writes read-only SQL behind parsed guardrails, checks that every figure in its answer comes from a query result, and shows the rows and every step. Visitors pick the model: Nemotron 3 Ultra or Ministral 14B. The same agent also runs as a LangGraph graph, and its tools are an MCP server that Claude Desktop or Cursor can use.

What measuring it showed

A one-sentence prompt rule stopped the model inventing currency symbols, and cost 2.3 of 12 hard questions: the model's SQL changed along with its wording. The fix moved into code, after the answer, where it cannot touch the queries.

The same code scored between 8.3 and 10.7 on the hard set across sessions with nothing changed. Since then every change runs interleaved with the committed code in the same session, and only a gain that repeats counts.

Ask Your Documents

Hybrid retrieval with cited answers

Ask questions of your own PDFs and notes and see exactly which passage each answer came from. FAISS dense retrieval and BM25 fused with Reciprocal Rank Fusion, citations validated against the passages they point at, and a plain “not in your documents” when the answer is not there. Double-click to run, no API key needed.

What measuring it showed

On terse keyword queries, dense retrieval dropped to 0.667 to 0.800 recall@3 where BM25 scored 1.000, and at k=3 BM25 alone was the safest retriever, not the hybrid I had built.

Swapping the embedding runtime for a ten times smaller install moved recall 13 points: the “same” model gave different vectors. And CI scored differently from my laptop with identical code, because rank-fusion ties were broken by absolute file paths.

How I work

Three rules the two projects taught me.

  • The evaluation is the product

    Anyone can assemble a pipeline. The useful part is the harness that says when it is wrong. It has contradicted me more than once, and each time the finding went into the README, including the fixes that did not work.

  • Guardrails are controls, not requests

    Asking a model to “only write SELECT” is a request. Parsing every statement before it reaches the database, rejecting stacked statements, DML hidden in a CTE and file-read functions, over a connection that is read-only on its own, is a control.

  • Written by hand first

    The agent loop, retrieval, rank fusion and provider adapters are my own code, because the interesting decisions live where a framework makes them quietly. Then the agent was rebuilt in LangGraph, and tests hold both to identical answers, steps and tool calls.
